# Player contract ownership

Tilecast shares contracts where independent implementations must agree, without moving unrelated platform code into one common package.

The contract owners are:

- **Public HTTP API:** `docs/openapi/core.yaml` plus plugin fragments, composed by `pluginctl`. The generated Go client and TypeScript API schema, Server route parity, Redocly, and oasdiff consume it.
- **Player manifest wire schemas:** `packages/manifest-schema`, consumed by the Server compiler, Android, Electron, and Edge.
- **Declarative presentation capability vocabulary:** `packages/manifest-schema/presentation-capabilities.json`, which generates Go, TypeScript, Rust, and Kotlin tables. Host profiles choose either the baseline or shared-runtime set.
- **Widget component capabilities:** Widget manifests, generated by `widgetctl`. These deliberately remain separate from the legacy declarative vocabulary.
- **Shared playback behavior:** `packages/player-runtime`, exercised by Electron/WPE/Android runtime conformance.
- **Pure presentation decisions:** `@tilecast/presentation-model` is the target owner for deterministic decisions shared by Studio and Runtime. The Core extraction must follow its ownership as that work lands.
- **Native Player implementation:** the accepted [`Player Core contract`](player-core.md) defines five shared Rust crates. These crates are not yet implemented. Core is an implementation owner, not a replacement for the natural contract owners below.
- **Activity semantics:** `packages/api-schema/activity/player-parity.json` and the Activity event contract pin proof-of-play behavior. Read [`activity.md`](activity.md) and [`activity-event-contract.md`](activity-event-contract.md) before changing these semantics.
- **Layout document:** `packages/layout-schema`, consumed by the Server, Studio, and Players.
- **Edge daemon/renderer IPC:** `packages/edge-protocol`, consumed by `tilecastd`, the WPE renderer, and migration/conformance fixtures.
- **Server URL normalization/security:** native platform implementations plus `packages/player-contracts/fixtures/server-url-policy.json`. Linux, Android, and Edge run the same fixture corpus.

## Generation

`npm run player-contracts:generate` reads the declarative capability registry and writes language-native mechanical bindings. `npm run player-contracts:check` fails when any generated binding is stale. Root `make generate` and `make generated-check` include these files.

The registry has two profiles. The **baseline** is the capability floor implemented by legacy supported Players. The **shared-runtime** profile adds capabilities implemented by the shared Player Runtime, currently `environment.time`. A host must advertise only the profile it actually runs; generation does not grant support by itself.

The Server URL fixture intentionally records only the product-wide policy floor: canonical HTTPS by default, explicit ports, LAN-scoped HTTP for private IPv4/link-local/localhost/`.local`, and rejection of public HTTP, credentials, paths, queries, fragments, and unsupported schemes. Platform-specific edge cases remain platform-owned until Tilecast deliberately versions them into this contract.

## Boundaries

This does **not** create a cross-language runtime library or FFI layer. Native
process lifecycle, kiosk integration, media transport, and OS APIs remain
platform-owned. Portable native state, verified content, and Server transport
move to the shared Rust layer through the Player Core extraction sequence.
Widget V2 remains generated from Widget manifests rather than this registry.

Keep fixtures at the rule's natural owner. OpenAPI owns Player HTTP contracts.
Manifest and Layout schemas own their wire documents. Player Runtime owns
execution conformance. Widget manifests own component capabilities.
`packages/player-contracts` contains only cross-player fixtures without another
natural owner. `packages/edge-protocol` remains Edge-local wire framing and
serialization. Core must not depend on it.
