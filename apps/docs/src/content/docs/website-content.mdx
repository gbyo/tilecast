Tilecast Players load Website Apps on the display. The page and its resources must be reachable from the Player; Tilecast Server does not download a copy of a website for offline playback.

## Create a Website App

<Steps>

1. In Studio, open **Content** > **Widgets** and select **Create Widget**.
2. Choose **Website** from the catalog.
3. Under **Content**, enter the public address in **Web address**.
4. Under **Behavior**, set **Reload** and **If the page cannot load**. Open **Advanced** to set the **Load timeout (seconds)**, **Allowed hosts**, JavaScript, storage, cookies, and the user agent. The page's own host is always allowed; add other hosts only when the site needs to navigate to them.
5. Under **Style**, set the zoom, scroll position, and background color if the page needs them.
6. Select the name in the header to rename the Widget, then select **Save Widget**.

</Steps>

The editor previews the page in a browser frame. Some sites refuse to appear inside another page; screens show them in their own isolated player view. To see what screens report when they load the page, select **⋯** > **Diagnostics**.

The Website App appears in the Media library's **Websites** filter and in the content picker. Add it to a Playlist as fullscreen content or place it in a Layout with other content.

## Add a Canva design

<Steps>

1. In Canva, open your design and select **Share** > **See all** > **Embed**. Publish a **public** embed. A public view link alone doesn't enable embedding.
2. Copy the **Smart embed link** or the `src` address from the HTML iframe. Tilecast accepts the address, not the full HTML code.
3. In Studio, create a **Canva** Widget and paste the link into **Canva design link**. Public design view links and `https://canva.link/...` links that redirect to a design view are also accepted. Tilecast resolves short links automatically when you preview or save.
4. Set **Reload interval**, name the Widget, then select **Save Widget**. Assign it to a Playlist or Layout after testing on your target Player.

</Steps>

Tilecast keeps the design's access path and query parameters, removes `utm_*` tracking fields, and selects Canva's embed view. Editor, template, presentation-control, and published website links aren't supported by the Canva Widget. If a short link is expired or can't be resolved, copy a new public embed link from Canva.

Studio's production security policy blocks external Canva frames. Studio reports a confirmed block and keeps **Open in Canva** available. In environments that allow external frames, Studio labels the attempted preview **unverified**: a browser frame can report loading even when Canva shows an access error or blocks embedding. If the preview is blank, select **Open in Canva**, check that the embed is still published, and test the embed address in a signed-out browser. Private embeds require a Canva account and cookie access; they aren't suitable for unattended Tilecast playback. See [Canva's embedding instructions](https://www.canva.com/help/embed-designs/).

Canva needs a network connection and a Player with periodic web reload support (`web.remote@2`). Updated Android, Edge, Windows, and legacy Linux Electron Players provide that contract. Browser Player currently can't play remote websites or Canva. Studio uses a browser iframe; native Players use isolated web views. A working Studio preview doesn't establish that a particular TV or browser engine can play the design. Test the actual device, including fullscreen, Layout sizing, reload, and network recovery.

Tilecast doesn't control Canva autoplay, looping, or page timing. For a timed presentation, export an MP4 and upload it as [media](../media/). For static or offline content, export an image or PDF. See the [Canva engineering contract and manual checks](https://github.com/gbyo/tilecast/blob/main/docs/widgets-and-layouts.md#canva-link-and-preview-contract) for supported URL shapes and platform verification.

## Choose where the Player can connect

Use HTTPS for public websites. HTTP is accepted only when both the server environment variable `TILECAST_WEBSITE_ALLOW_PRIVATE_HTTP=true` and **Settings** > **Websites** > **Private HTTP enabled** allow it, and the URL uses a private-network host.

The allowed-host list limits top-level navigation. It does not block every third-party resource a page may request. Website Apps do not support imported login cookies, OAuth tokens, or Tilecast credentials. A site that requires an unsupported sign-in flow may not work.

## Plan for interruptions

Website playback needs a network connection from the Player. If the site cannot load, choose what **If the page cannot load** does: keep the last page that loaded, show a fallback image, show the Tilecast placeholder, or skip the item. Set the **Load timeout (seconds)** and **Reload** to match the site. The Playlist item duration controls how long the website plays.

Check that the exact display can reach the site. A page can work in your browser but fail on a TV or Linux Player because of DNS, network filtering, unsupported site behavior, or a site that blocks embedded browsers.
