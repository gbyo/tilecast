---
title: Monitor Tilecast Edge
description: Use Fleet, Activity, proof of play, telemetry, and live preview with Tilecast Edge screens.
---

An Edge screen appears in the same Studio tools as every other Tilecast Player. You don't need a separate monitoring workflow.

## Screen status and Activity

Edge reports its connection, the current presentation and item, schedules, Takeovers, synchronization, playback progress, and available hardware features. Use [screen status](../../operations/screen-status/) for the Fleet status meanings and [Activity](../../operations/activity/) for proof of play, playback history, and incidents.

When the server is unreachable, Edge keeps its Activity events on the computer and sends each one once after it reconnects. A very long outage keeps the newest events and tells the server how many older ones it dropped, so Activity shows a gap instead of invented playback.

## Telemetry

Edge reports Player health such as connection and playback state, renderer state, content cache use, storage, uptime, and clock offset.

## Live preview

Edge answers Studio's normal [Live preview](../../operations/live-preview/) with a snapshot from the renderer. Setup, pairing, and safe-mode screens aren't captured. If the renderer can't take a snapshot, Edge pauses previews for a while instead of risking playback.

**Watch live** isn't available on Edge.

## Updates

**Deployment history** in **Settings** > **Player updates** shows each Edge screen's update state, including rollbacks and their reasons. See [Update Tilecast Edge](../updates/).

When an Edge screen needs attention, start with Fleet, Activity, and live preview. Use the [local status and logs](../troubleshooting/#local-status-and-logs) when Studio doesn't show enough.
