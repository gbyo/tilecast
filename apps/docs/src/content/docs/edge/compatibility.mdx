title: Content compatibility
description: Check whether a screen's content can play on Tilecast Edge before you migrate it, and what Edge does with content it can't show.
---

Edge keeps playing the last presentation it could show if a newer one needs a feature it doesn't have. It reports the reason to Studio instead of showing a partial or blank presentation.

## Content that plays on Edge

Edge plays images, downloaded video, native Widgets (including Clock, Date, World Clock, and Countdown), Layouts and playlist zones, transitions, direct assignments, schedules, Takeovers, Quick Present, synchronized Display Groups, unrotated Span content, status screens, and the Brand Bug, Countdown Bar, alert ticker, and Noise Meter plugins.

For large videos and items marked for streaming, Edge downloads and verifies the complete file before it plays it. The item starts a little later the first time, and it keeps playing offline afterward.

## Content Edge can't show yet

- **Websites, YouTube, and web Widgets.** Edge doesn't run remote web content until the website isolation work in M11 is done.
- **Rotated Span panels.** Edge rotates Span content the same way as the stable Linux Player, but rotation isn't verified on a physical wall yet.

Codecs, hardware video decoding, and multi-panel frame alignment also still need testing on real hardware. See the [capability matrix](../capabilities/) for the full comparison.

## Check a screen before you move it

Review these in Studio for the screen you plan to migrate:

- its direct assignment and upcoming schedules;
- Layout zones and Widgets;
- synchronization or Span requirements;
- installed plugins;
- Website or YouTube content;
- Display Control and other hardware features.

The [migration](../migrate/) also checks the screen's current presentation before it stops the stable Linux Player, and refuses to switch if Edge can't show it.
