## Show data from another service

To show information that lives somewhere else, such as a calendar, a news feed, a spreadsheet, or a weather forecast, create a [Data Source](../data-sources/). Tilecast Server fetches the data on a schedule, and a [Widget](../widgets/) shows it on screen. You don't need a token for this.

## Which one do I need?

| You want to                                                 | Use                                                                                                              |
| ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Run Tilecast tasks from a terminal                          | The [CLI](./cli/), signed in through your browser                                                                |
| Run Tilecast tasks from a script or CI job                  | The [CLI](./cli/) or the [HTTP API](../reference/api/) with a [personal access token](./personal-access-tokens/) |
| Let an AI assistant read or manage Tilecast                 | [MCP](./mcp/), preferably with `--read-only` or a read-only credential                                           |
| Keep a Manual Table in sync with another system             | An [integration token](./tokens/) with **Write Manual Table rows**                                               |
| Monitor screen health from Prometheus or another monitor    | An [integration token](./tokens/) with **Read fleet health**                                                     |
| Get told when something goes wrong                          | [Email or webhook notifications](./notifications/)                                                               |
| Show a calendar, feed, spreadsheet, or forecast on a screen | A [Data Source](../data-sources/) and a [Widget](../widgets/)                                                    |

Plugins can add their own CLI commands and MCP tools. See [Commands from plugins](./cli/#commands-from-plugins).
