title: Connect a Data Source
description: Create reusable, cached data connections for Widgets and live text in Layouts.

A **Data Source** connects Tilecast to structured information that a Widget or Layout can display. The source holds the data; the [Widget](../widgets/) or text binding controls how it appears. Tilecast Server fetches remote sources and caches the parsed data, and Studio shows the source's status and refresh diagnostics.

Because the two are separate, one source can feed several displays. A Google Sheet of club meetings can drive a Table in the office and a Ticker in the hallway.

## Create a Data Source

<Steps>

1. Open **Content** > **Data Sources**, then select **Create Data Source**.
2. Choose a provider from the catalog offered by your Tilecast Server. Providers include **RSS / Atom Feed**, **Calendar**, **Google Sheet**, **JSON**, **CSV**, **Weather**, **Transit**, alerts, and tables you edit in Studio, such as **Manual Table**, **Announcements**, **Events**, and **Menu Items**.
3. Follow the setup checklist for that provider. Enter its connection details, map the values to typed fields when prompted, and review the preview when one is available.
4. Select **Save Data Source**.

</Steps>

The provider determines what you configure. For example, a public calendar needs an ICS feed URL; a JSON or CSV source needs field mappings; a **Manual Table** lets you define typed columns and enter up to 200 rows in Studio. Installed plugins can add providers; Forms, for example, publishes approved submissions as a Data Source. The [content definition reference](../reference/content-definitions/) lists the providers in your Tilecast version.

You can also create a Data Source from a Widget or Layout editor. Select **Connect new data** in the **Choose data** list. The list shows only sources that the Widget or binding can use.

## Feeds

Use **RSS / Atom Feed** for news, blog posts, and other published updates. Tilecast detects whether the address serves RSS or Atom and reads both into the same kind of records. Choose a **Publisher preset**, such as **New York Times — Top Stories**, or **Custom URL** to enter any feed address.

Tilecast marks what each feed field means: the title is the headline, the description is the summary, and the date is the publication time. Feeds also carry the source name, author, and link when the publisher provides them. News, Ticker, and other Widgets use these meanings to fill in their fields, so you rarely map feed fields by hand. Tilecast removes HTML from feed text and never displays it as a web page.

Feed content belongs to its publisher. Confirm that you may show a feed before you use it, and credit the publisher on screen. News can show the source name for this.

Studio used to offer separate **RSS** and **Atom** providers. Sources you created with them keep refreshing and working. New feeds use **RSS / Atom Feed**.

## Spreadsheets: data or display

Google Sheets can reach a screen in two different ways:

- The **Google Sheet** Data Source reads the rows of a published sheet as records. Use it when a List, Table, Cards, Ticker, or News Widget should show the rows in Tilecast's own design.
- The **Google Sheets — Display** App shows the published spreadsheet itself, as Google draws it. Find it in **Content** > **Widgets** with the other web Apps. See [Website Apps](../website-content/).

Both read only a sheet that is published to the web. Tilecast can't read a private sheet.

## Use its data

In a Widget editor, choose a compatible Data Source under **Data**. Studio fills in the Widget's fields from the source, and you can change each one. See [Create a Widget](../widgets/#create-a-widget). In a Layout, select a text layer, switch **Content mode** to **Dynamic field**, then choose a Data Source and field. For a structured, repeatable display such as a list or ticker, use a Widget rather than a single text binding.

One Data Source can feed several Widgets and Layout bindings. Studio's Data Source details show where it is used. If you need to remove a source, first remove every Widget and Layout binding that uses it; Tilecast prevents deleting a source that is still referenced.

## Check a source that looks out of date

Open the Data Source and check **Last success**, **Last attempt**, its status, and whether the displayed values are cached. A failed refresh can leave cached values available, so an old value may still appear while the upstream connection is unavailable. Check the source URL and the server's network access before changing the Widget.

Tilecast Server makes the remote request. The default `TILECAST_SOURCE_ALLOW_PRIVATE_NETWORKS=false` policy blocks private-network destinations. An administrator must change this setting if a source is intentionally hosted on the installation's private network. A source hosted elsewhere must be reachable from the server, not only from your browser or the Player.
