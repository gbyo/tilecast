The Tilecast iOS app is a native home for Tilecast Studio. It handles the things an iPhone or iPad does better than a browser tab, such as switching between servers, and it shows your server's own Studio for everything else. The app isn't in the App Store yet. You can build it from source with Xcode.

## Where a feature belongs

Build a new feature in Studio. The app loads Studio from each server, so a new page, a new editor, or a plugin page works in the app as soon as the server is updated, with no Swift changes and no app release.

Native code is for app chrome, system features like the camera or Share sheet, and a few small, stable workflows. The full rules are in the [iOS app architecture](https://github.com/gbyo/tilecast/blob/main/docs/ios-app.md).

## Build and run

You need Xcode 26 or later. The app has no third-party packages.

1. Open `apps/ios/Tilecast.xcodeproj`.
2. Run the **Tilecast** scheme on an iOS 26 simulator.
3. Tap **Add Server** and enter your server's address. For a local development server on the same Mac, use `http://127.0.0.1` with your server's port.

Each server keeps its own sign-in and website data, so you can add several installations and switch between them from the title menu.

To run on a device, copy `apps/ios/Config/Local.xcconfig.example` to `Local.xcconfig` and set your Apple team.

## Test

```sh title="apps/ios/TilecastKit · Core tests on the Mac"
swift test
```

The full simulator suite, the localization check, and the architecture check are listed in [`apps/ios/README.md`](https://github.com/gbyo/tilecast/blob/main/apps/ios/README.md). CI runs them whenever a pull request changes `apps/ios/`.

On sign-in, iOS shows its system authentication consent sheet for the configured server, then opens that server in the system authentication browser. Passwords, passkeys, authenticator codes, and recovery codes stay on the server's real origin. After approval, the app receives an ordinary Studio session for that server. See the [iOS authentication contract](https://github.com/gbyo/tilecast/blob/main/docs/ios-app.md#authentication).

## Server addresses

The app accepts the same addresses as Tilecast Players. Servers on the internet need HTTPS with a certificate your device trusts. Plain HTTP works only for local network addresses, such as `192.168.1.20` or `tilecast.local`, and the app warns you before it saves one.
