title: Write the plugin manifest
description: Declare a plugin's identity, capabilities, entry points, routes, runtime surfaces, and public docs.
---

The manifest is `plugins/<name>/tilecast.plugin.json`. Tilecast validates it at build time and when the server hosts the plugin.

Use the generated JSON Schema in your editor. The exact field rules live in the [Plugin API v2](https://github.com/gbyo/tilecast/blob/main/docs/plugin-api-v2.md#manifest) and [Plugin API v1](https://github.com/gbyo/tilecast/blob/main/docs/plugin-api.md#manifest) engineering references.

## Identity

These fields describe the plugin in the catalog:

- `apiVersion` is `2` for a new plugin. Existing plugins use `1`.
- `id` is the stable snake_case identifier.
- `definitionVersion` versions the plugin's persisted and Player-facing definition.
- `name`, `description`, `category`, and `icon` describe it in Studio.
- `maintainers` lists the people or teams responsible for the subject.
- `instanceNoun` gives the singular and plural name shown with instance counts.
- `requirements` tells an operator what the plugin expects before installation.
- `uses` is plain catalog text describing the Tilecast capabilities it uses.

The directory name is the ID with underscores changed to hyphens.

## Capabilities

Only declare capabilities the implementation uses.

```json
{
  "capabilities": {
    "playerManifest": true,
    "backgroundWorkers": true,
    "network": ["api.example.org"]
  }
}
```

`backgroundWorkers` is required for a `WorkerProvider`. `network` lists server-side hosts the plugin contacts. In Plugin API v1 only, `playerManifest` is required when the server projects Player manifest entries; a v2 plugin declares a `player` contribution instead.

`plugin.CheckDeclarations` compares the manifest with the Go interfaces the plugin implements.

## Entry points

The build uses fixed paths:

```json
{
  "server": { "entrypoint": "./plugin.go" },
  "studio": {
    "route": "/plugins/transit-alerts",
    "entrypoint": "./studio/index.tsx"
  },
  "runtime": {
    "entrypoint": "./runtime/index.ts",
    "manifestTypes": ["transit_alert"],
    "surfaces": ["strip.bottom"],
    "tier": "scheduled"
  }
}
```

Leave out `studio` when the plugin has no Studio pages.

## Player contribution

In Plugin API v2, Player behavior is its own optional contribution. Leave out `player` entirely when the plugin does nothing on screens.

```json
{
  "player": {
    "state": [{ "type": "transit_alert", "version": 1 }],
    "runtime": {
      "entrypoint": "./runtime/index.ts",
      "services": {
        "required": ["player.clock@1", "player.surface@1"],
        "optional": ["player.presentation.observe@1"]
      },
      "surfaces": [
        { "id": "ticker", "slots": ["strip.bottom"], "tier": "scheduled" }
      ]
    }
  }
}
```

- `state` lists the Player state types the plugin's server projects and its Player behavior reads.
- `runtime` is portable Player behavior in the Shared Runtime. `services` lists what it needs; a Player without a required service doesn't run it, and a missing optional service is just unavailable.
- `surfaces` gives each visual contribution its own slots and tier. Only declare it when you request `player.surface@1`.
- `native` lists first-party native contributions, each a Rust crate in `native/<id>/`. The crate exports `contribution()`, and `plugins:generate` links it into the Player builds that include native plugins.
- `events` lists the ephemeral events between your native part and your Shared Runtime part: a `name`, a `version`, and the `source` that raises it (`native` or `runtime`). Declare it with `player.events@1` and both parts.
- `providers` (inside `runtime`) lists the presentation providers you offer with `player.presentation.provide@1`.

Plugin API v1 plugins declare a `runtime` member with `manifestTypes`, `surfaces`, and one `tier` instead.

## API routes

A plugin with HTTP routes declares the prefixes it owns and its OpenAPI fragment:

```json
{
  "api": {
    "basePaths": ["/plugins/transit-alerts"],
    "openapi": "./api/openapi.yaml"
  }
}
```

The server refuses route collisions with core or another plugin.

## Studio routes

`studio.route` is the management route under `/plugins/<directory>`.

Use `studio.additionalRoutes` when the plugin owns a separate Studio surface such as a portal or inbox. The Studio definition must contribute matching `standaloneRoutes`.

## Store listing

A plugin can dress up its Plugin Store page with a second file, `plugins/<name>/tilecast.store.json`. It holds presentation only:

```json
{
  "publisher": { "name": "Tilecast", "url": "https://tilecast.org" },
  "longDescription": "A few sentences for the page's About section.",
  "artwork": {
    "icon": "./store/icon.webp",
    "screenshots": [
      { "src": "./store/01-overview.webp", "alt": "What the screenshot shows." }
    ]
  }
}
```

Keep the images in the plugin's `store/` folder as `.webp` or `.png`. Use up to five screenshots at one size, 16:9 (about 1920 × 1080), and write alternative text for each. Attach the file in `plugin.go` with `.WithStore(...)`. Tilecast checks the paths when the server starts, so a typo is a build failure rather than a broken image.

The file never changes what the plugin is or does. Identity, requirements, capabilities, and trust all still come from `tilecast.plugin.json`. A plugin without a Store file still works and shows its built-in icon and no screenshots. See the [engineering reference](https://github.com/gbyo/tilecast/blob/main/docs/plugin-api.md#plugin-store-presentation) for every rule.

## Public docs

A plugin can publish pages from its own directory:

```json
{
  "docs": {
    "pages": [
      {
        "source": "./docs/index.mdx",
        "slug": "operations/plugins/transit-alerts"
      }
    ]
  }
}
```

The docs build checks slug collisions and adds declared pages to the public docs collection. The docs sidebar doesn't list plugin pages. Link your page from the plugin catalog page, `apps/docs/src/content/docs/operations/plugins.mdx`, so readers can find it. A docs test fails when a declared page has no link there.
