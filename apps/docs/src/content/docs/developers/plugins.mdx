A Tilecast plugin is one directory below `plugins/`. Tilecast discovers its server code, Studio pages, Player runtime, migrations, API description, and public docs from that directory.

Plugins ship with Tilecast. Plugin API v1 does not download or run third-party code.

## Pick the part you need

- [Create a plugin](./create/) starts with `plugins:new` and gets a new plugin to a clean conformance check.
- [Write the manifest](./manifest/) explains the fields in `tilecast.plugin.json`.
- [Add server behavior](./server/) covers Host services, routes, workers, status, removal blockers, and Demo Mode.
- [Add Studio pages](./studio/) covers management routes, standalone routes, translations, and secondary navigation.
- [Draw on the Player](./player/) covers manifest projection, surfaces, tiers, CSS, and runtime tests.
- [Publish a Data Source or private asset](./data-sources/) covers `DataSourceProvider`, `Host.DataSources`, and `Host.PluginAssets`.
- [Add migrations and tests](./testing/) covers the global migration sequence, conformance, PostgreSQL tests, and generated files.

For the exact API contract, use the [Plugin API v1 engineering reference](https://github.com/gbyo/tilecast/blob/main/docs/plugin-api.md).

## What belongs in a plugin

<FileTree>

- plugins/
  - transit-alerts/
    - tilecast.plugin.json Identity, capabilities, and entry points.
    - plugin.go Go entry point.
    - plugin_test.go Conformance test.
    - server/ Optional server implementation.
    - migrations/ Optional Goose migrations.
    - api/openapi.yaml Optional API description.
    - studio/ Optional Studio pages and translations.
    - runtime/ Optional Player runtime and styles.
    - docs/ Optional public docs pages.

</FileTree>

The plugin ID uses underscores. The directory uses hyphens, so `transit_alerts` lives in `plugins/transit-alerts/`.

The build owns the few files that list every plugin. Run `npm run plugins:generate` instead of editing those files by hand.

## Use the existing plugins as examples

The three bundled plugins cover different parts of the API:

- [Countdown Bar](https://github.com/gbyo/tilecast/tree/main/plugins/countdown-bar) is the smallest Player-facing example. It has Studio configuration, a manifest projector, and shared-runtime surfaces.
- [Emergency Alerts](https://github.com/gbyo/tilecast/tree/main/plugins/emergency-alerts) shows routes, background work, network access, Takeovers, and an emergency Player surface.
- [Forms](https://github.com/gbyo/tilecast/tree/main/plugins/forms) shows a larger workflow plugin with standalone Studio routes, secondary navigation, a Data Source provider, private assets, and PostgreSQL-heavy tests.

Start with the example closest to what you are building. Don't copy a contribution interface that your plugin does not need.
