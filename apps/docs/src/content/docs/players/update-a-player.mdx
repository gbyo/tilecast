Use **Settings** > **Player updates** to choose and deploy a verified Android, Linux, Tilecast Edge, or Windows release. Updating a release does not update Tilecast Server, Docker, or the host operating system.

## Deploy to screens

<Steps>

1. Open **Settings** > **Player updates** and select **Deploy update**.
2. Choose the **Player type** and **Version**. Edge and Windows show human-readable CPU choices: **Intel / AMD 64-bit** (`x86_64`) and **ARM64** (`aarch64`). If only one build applies, Tilecast selects it automatically.
3. If the selected build is not on the server yet, select **Prepare build**. The server downloads and verifies it in the background. You can close the deployment dialog while that continues.
4. Choose the target screens or Display Groups. Tilecast checks the resolved screens for Player type, architecture, current version, and known platform requirements.
5. Choose the deployment mode. **Install now** is the normal path; **Download only** stages the update without installing, and **Maintenance window** installs at or after the selected local time.
6. Open **Rollout safeguards** if you want a canary cohort, then review the update and select **Deploy update**.

</Steps>

You do not need to visit **Release catalog** before deploying. Use that view when you need to sync the catalog, inspect release notes and verification, upload signed files, manage cached builds, or select an older version.

An offline screen receives the update after it reconnects within the command-expiry window. The **Needs attention** queue surfaces rollouts that require operator action, while healthy updates stay under **In progress**. Cancelling a deployment stops screens that have not finished; it does not roll back screens that already updated.

## What to expect on each platform

<Tabs syncKey="player-platform">

<TabItem label="Android TV">

The Player downloads and verifies the APK. Android may require the install permission on the Player and may show a local install confirmation. The first-time checklist includes **Allow signed Player updates**.

</TabItem>

<TabItem label="Linux">

The managed AppImage downloads and verifies the release, replaces the running file, and restarts. The AppImage and its parent directory must be writable by the kiosk account. Use the [server-provided Linux installation](../install-linux/) to create the supported managed setup.

</TabItem>

<TabItem label="Tilecast Edge">

The screen downloads and verifies the release, installs it beside the current release, and restarts into it. It confirms the update after it reconnects and shows content for two minutes. If it can't, it returns to its previous release on its own and the deployment shows the screen as failed. See [Update Tilecast Edge](../../edge/updates/).

</TabItem>

<TabItem label="Windows">

Once a signed Windows release is published, the Player downloads its package from the paired server, verifies the release signature and the Windows publisher identity, installs the package, and restarts into the new version. It stays on its own architecture: an ARM64 screen never installs an x64 package. The PC must trust the Windows publisher certificate; see [Windows installation](../install-windows/) and [update troubleshooting](../../troubleshooting/player-updates/).

</TabItem>

</Tabs>

If an Android TV is waiting for someone to approve the install, complete the prompt on that TV. If a Linux update fails, confirm that Tilecast Player is running from the installed AppImage and that the kiosk account can write to its file and directory.
