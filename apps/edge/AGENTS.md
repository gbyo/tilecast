# Tilecast Edge agent guide

This file applies to `apps/edge/`. The repository `AGENTS.md` also applies.
Read [`docs/tilecast-edge.md`](../../docs/tilecast-edge.md) (with Amendment A1)
and [`docs/tilecast-edge-next.md`](../../docs/tilecast-edge-next.md) before a
change. The RFC is binding. If a change must deviate from it, stop and write
the complete tradeoff first.

## Fixed decisions

- `tilecastd` runs as the fixed `tilecast` account. The renderer runs as the
  same account in a separate, more restricted unit.
- The Linux renderer is WPE WebKit 2.54+ on the WPEPlatform API. Do not add
  Cog, libwpe, WPEBackend-fdo or an Electron renderer bridge.
- The transition is one way: legacy Electron installation, one-time verified
  import (`tilecastd import-legacy`), Edge plus WPE. Do not add shadow modes,
  credential leasing or CSR delegation through another process.
- Everything that is not visual rendering belongs in `tilecastd`.
- The change feed is monotonic, not gapless. Continuity is the signed
  `previousSequence` chain. Never treat a missing integer as a lost change.
- Zenoh is transport and wake-up only. The server is authoritative.

## Review rules (RFC §48)

1. No new root privilege without a written threat-boundary review.
2. No shell invocation with interpolated values. `tilecastd` starts no
   processes.
3. No arbitrary path from server, peer or renderer input. CAS paths come from
   digests. Download paths pass `OriginBlobSource::new` validation.
4. Bound every network read, body, frame, list and string. Use the bounded
   types in `edge-protocol`.
5. Apply peer-relayed authoritative state only after server signature
   verification (`edge_server::feed`). Peer statements are never
   authoritative.
6. Content bytes are not trusted until the content store verifies hash and
   size. A source never decides integrity.
7. A durable state transition that can duplicate a command or update needs a
   crash-point test.
8. An optional provider failure must not stop playback initialization.
9. Every capability must distinguish unsupported, blocked and degraded, with a
   reason code.
10. Aggregate high-rate data before persistence or network use.
11. No secret in logs, tests, fixtures or screenshots. `DeviceCredential` and
    `NodeCredentials` redact themselves in `Debug`; keep it so.
12. An Edge and server protocol change needs cross-language fixtures in
    `packages/edge-protocol/fixtures` and tests on both sides.
13. A WPE change that touches remote website content needs a navigation,
    permission and data-isolation review.
14. Never claim a physical display state was confirmed when only a command was
    sent.
15. Never infer health from process or socket liveness when meaningful
    playback evidence is available.

## Identity and trust invariants

- Verify public installation identity before the device credential is sent.
  `AuthenticatedServer` exists only after `ServerClient::verify_installation`.
- The Edge private key is generated by `tilecastd`, stays in
  `identity/` (mode 0600) and never crosses IPC.
- The first enrollment pins the Edge CA and authority key. A different CA or
  authority is refused (`EnrollError::TrustChanged`) until authority rotation
  with overlapping epochs exists.
- `verify_peer` is the only fabric membership decision. Discovery, addresses
  and liveliness tokens never imply trust.
- Delete the device credential only when the server says it is invalid or
  revoked.

## Engineering conventions

- Rust 1.98, edition 2024, workspace lints. `unsafe_code` is denied.
- Format with `cargo fmt` (`max_width = 120`). Run
  `cargo clippy --workspace --all-targets -- -D warnings`.
- Keep the dependency direction in [`README.md`](README.md).
- Keep comments for behavior that the code does not show.
- Prefer real components and small fakes over mocks: tests run real sockets,
  real SQLite and real TLS on loopback.
- Before a completion claim, run the workspace checks, `ci/test-linux.sh` in
  the Linux image, and the end-to-end scripts that cover the change.
